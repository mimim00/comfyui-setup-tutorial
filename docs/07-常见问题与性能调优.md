# 07 · 常见问题与性能调优

## 1. 常见报错排查

| 现象 | 原因 | 解决方法 |
|---|---|---|
| 打不开 `127.0.0.1:8188` | 服务没起来 / 端口被占用 | 查看命令行是否出现 “To see the GUI go to” 字样；端口占用加 `--port 8189` 启动 |
| 界面里选不到模型 | 模型没放对目录 / 没刷新 | 检查 `models/checkpoints/` 等目录；重启 ComfyUI |
| 模型加载报错/损坏 | 下载不完整 | 核对哈希，重新下载；确认文件是 `.safetensors`/`.ckpt` |
| 缺自定义节点 / 缺依赖 | 加载了需要插件的工作流 | 装 ComfyUI-Manager → 一键安装缺失节点 |
| CUDA out of memory | 显存不足 | 加 `--lowvram` 或 `--novram` 启动；降低图片尺寸与步数；用小模型 |
| 提示词中文乱码/无效 | 多数模型不支持中文提示词 | 用英文提示词，或换支持中文的模型 |
| 路径含中文导致读取失败 | 路径编码问题 | 安装路径改用纯英文、无空格路径 |
| 下载模型很慢 | 网络问题 | 用 `HF_ENDPOINT=https://hf-mirror.com` 镜像或下载器续传 |
| 更新后报错 | 版本/依赖冲突 | 用 `update/update_comfyui_and_python_dependencies.bat`（便携版）或 `git pull` + `pip install -r requirements.txt` |

## 2. 无独显 / CPU 模式调优

如果你只能在 CPU 上跑（例如 i5-13500H + 核显）：

- 启动加 `--cpu`（便携版双击 `run_cpu.bat`）。
- **内存大就让它吃内存**：32GB 内存可正常加载中小模型。
- 降低负担的关键参数：
  - 出图尺寸：512×512 或更低
  - 步数：20 以内
  - 采样器：`euler`（更快）
- 预期：一张 512×512 小图可能需要数分钟，耐心等待或转云端。

## 3. GPU 显存优化

- `--lowvram`：低显存模式，自动分块加载
- `--novram`：更保守，显存极小（≤4GB）时用
- `--force-fp16`：强制半精度
- 大模型（SDXL/Flux）建议显存 ≥8GB；实在不够用 [06-云端部署](06-云端部署.md)

## 4. 日常使用建议

- **定期更新**：ComfyUI 迭代快，用稳定版脚本更新更稳妥。
- **备份工作流**：`.json` 工作流文件建议存到 Git 或网盘。
- **管理模型**：不用的模型及时清理，模型动辄几 GB，占盘严重。
- **注意 License**：商用前确认所用模型的授权条款。
